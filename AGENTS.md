# AGENTS.md — Omni-Foní

Open-source clean-room BSS/OCS for VoIP operators. Master plan in `docs/master-plan.md`, read it before any implementation work.

## Status

- P0 foundations + first P1 slice: `services/charging`, the OCS core (gRPC `Authorize`/`Charge`/`Release`, `proto/charging/v1/charging.proto`).
- P1 slice two: `services/switching` on :50052, the call-lifecycle caller against the OCS (gRPC `StartCall`/`StopCall`/`CallEvents`, `proto/switching/v1/switching.proto`). Charges every whole second; terminates within one tick of exhaustion; fail-closed (`ocs_unavailable`) when Charging is unreachable. `make protoc` regenerates all service protos (catalogue, charging, switching, mediation, billing, payments, routing, sbc, reconciliation) (needs protoc and protoc-gen-go/-go-grpc in /root/go/bin; the Makefile PATHs them).
- P1 slice three: `services/catalogue` on :50053 owns all rates (gRPC `GetRate` longest-prefix match / `PutRate`, `proto/catalogue/v1/catalogue.proto`, rates table in the `catalogue` DB). Charging resolves rates from Catalogue over gRPC and fail-closes (`internal_error`) if it's unreachable; the charging DB has no rates table anymore (stale one may linger in old volumes, drop if it bothers you).
- P2 slice one: `services/mediation` consumes `cdrs.raw`, validates, dedups via the mediation DB `cdrs` ledger (call_id PK), publishes `cdrs.normalized` (and `cdrs.rejected` dead letters with a `reason` header), then commits Kafka offsets. No gRPC port. `services/switching` publishes one `mediation.v1.CallCdr` (proto in `proto/mediation/v1/mediation.proto`) to `cdrs.raw` on call end via franz-go; Kafka addr envs are `SWITCHING_KAFKA` (default localhost:9092) and `MEDIATION_KAFKA` (default kafka:9092). Mediation is at-least-once with a tiny crash-window duplicate; Billing dedups by call_id. Design: `docs/superpowers/specs/2026-11-12-mediation-design.md`.
- P2 slice two: `services/billing` on :50054 consumes `cdrs.normalized` (group `billing`, AtStart, manual commit after each batch), rates each CDR via Catalogue (missing rate → `cdrs.billing.rejected` dead letter, not retried), and writes one `invoice_lines` row per call into the `billing` DB (call_id PK = the dedup; the insert carries final values so crash replays are idempotent). Cost = ROUND(seconds*rate), same money rule as the OCS. gRPC `GetInvoice(account, period)` serves per-period totals; periods are YYYY-MM from the CDR's start time in UTC. Envs: `BILLING_KAFKA` (default kafka:9092), `BILLING_CATALOGUE_ADDR` (default catalogue:50053).
- P2 slice three: `services/payments` on :50055 is the HTTP webhook surface: `POST /webhook/{gateway}/payment` verifies the Stripe-Signature scheme (HMAC-SHA256 over `t.<payload>`, `t=...,v1=...` header, ±5 min timestamp window), then records the payment into the `payments` DB keyed by the gateway event id (`event_id UNIQUE` = webhook idempotency; replays 200 with no second row, at-most-once money recording). Envs: `PAYMENTS_WEBHOOK_SECRET` (dev default `dev-only`), `PAYMENTS_ADDR` (default :50055). gRPC `GetPaymentsTotals`/`ListAccountsForPeriod` on `PAYMENTS_GRPC_ADDR` (default :50060) serves reconciliation (recorded payments only; period = YYYY-MM of `created_at` UTC). PayFast/PayPal adapter specifics are still open.
- P2 slice four: `services/reconciliation` on :50059 is the read-only money-triangle aggregator (gRPC `ReconcileAccount`/`ReconcilePeriod`, `proto/reconciliation/v1/reconciliation.proto`). No DB: it reads Billing (`GetPeriodLedger`, `GetInvoicesByAccounts`, `ListAccountsForPeriod`) and Payments (`GetPaymentsTotals`, `ListAccountsForPeriod`) over gRPC. Billing maintains the `cdr_period_totals` ledger transactionally with each new `invoice_lines` insert (replays touch neither table), so ledger-vs-invoice mismatch is genuine drift. The sweep (env `RECONCILIATION_SWEEP_INTERVAL`, default 15m, `0` disables) scans current+previous month: ledger drift is warned and published as proto `DriftEvent` to `reconciliation.drift` (`RECONCILIATION_TOPIC_DRIFT`); payment deltas are info logs only (AR states, not drift); on-demand RPCs report and never publish. Envs: `BILLING_ADDR` (billing:50054), `PAYMENTS_ADDR` (payments:50060), `RECONCILIATION_KAFKA` (kafka:9092).
- P3 slice one: `services/identity` on :50056 is HTTP-only (stdlib mux, no OIDC/OpenAPI yet): `POST /bootstrap` creates the first tenant+admin only while the users table is empty (409 afterwards); `POST /sessions` logs in (bcrypt, same 401 for unknown email and bad password); `POST /users` (admin-only, 403 otherwise) creates users with role `admin|reseller|user`; `GET /me` (any valid session bearer token) reports email/role/tenant. `POST /tenants` (admin-only) registers additional tenants; `POST /accounts` + `GET /accounts?tenant_id=` manage the account↔tenant registry (admins any tenant, resellers own tenant only, users 403; the P3 zero-cross-tenant gate is tested here). `GET /commission?tenant_id&period` joins tenant→accounts→billing (`IDENTITY_BILLING_ADDR`, default localhost:50054, via the billing gRPC `GetInvoicesByAccounts` batch added to `proto/billing/v1/billing.proto`) and reports per-account billed totals; resellers are scoped to their own tenant, admins any. Sessions are opaque 32-byte random tokens in the `identity` DB with 24h expiry. Tests TRUNCATE sessions/users/tenants/accounts CASCADE at start (dev-only convenience). Envs: `IDENTITY_DSN`, `IDENTITY_ADDR` (default :50056). Reseller hierarchy depth, commission *rates* (the report is raw billed totals), OIDC, OpenAPI 3.1 and HTTPS-at-edge are still open.
- P3 slice two: `services/routing` on :50057 is the dial plan (gRPC `Resolve` longest-prefix / `PutRule` upsert, `proto/routing/v1/routing.proto`, rules table in the `routing` DB). `Resolve` returns an empty `trunk_id` for no match (callers decide to fail closed), not an error. Switching consults Routing in `StartCall` (`SWITCHING_ROUTING_ADDR`, default localhost:50057): unrouted destinations deny with `no_route`, a Routing outage denies with `routing_unavailable`, both before the OCS Authorize. The registry's resolver is optional (nil skips dial-plan resolution; tests construct `startSwitchingFull` with a resolver or nil).
- P4 slice one: Routing also does LCR (gRPC `PutLcrRoute`/`ResolveLcr`/`PutTrunk`, `lcr_routes`+`trunks` tables in the `routing` DB). `ResolveLcr` picks the cheapest *enabled* candidate for the number in one SQL query (left-anchored LIKE over a `text_pattern_ops` index); ties break longest-prefix then trunk id; cost is minor units per second; empty `trunk_id` means no enabled candidate. Verified on a 1000-route synthetic dataset (routing tests). Switching's call path now resolves via `ResolveLcr` (the plain `Resolve` dial-plan RPC remains for other callers) and carries the resolved trunk id onto the call and the published `CallCdr.trunk_id` (field 9); mediation republishes raw bytes verbatim, so it reaches `cdrs.normalized` without mediation-side code. Billing ignores it for now.
- P4 slice two: `services/sbc` on :50058 is the session-border policy engine (gRPC `CheckCall`/`EndCall`/`ReportAuthFailure`, `proto/sbc/v1/sbc.proto`, tables `barring_rules`+`trunk_limits`+`active_calls`+`auth_failures` in the `sbc` DB). `CheckCall` runs the playbook in order — source-IP block (≥5 `ReportAuthFailure`s from one IP inside 1 min → `ip_blocked`), destination then caller-id barring (longest-prefix → `barring_destination`/`barring_cli`), then reserves one slot on the trunk (advisory-lock + `active_calls`; denies `trunk_limit_exceeded` past `max_calls`); a denied call never reserves a slot. Switching consults it in `StartCall` (`SWITCHING_SBC_ADDR`, unset skips the playbook; compose sets `sbc:50058`): after routing/LCR resolves a trunk and before the OCS `Authorize`, an SBC denial returns its reason and an SBC outage denies `sbc_unavailable`, both fail-closed; `EndCall` releases the slot on every path that does not start, the live call releases it at end. `StartCallRequest` gained `source_ip` (field 4; empty skips the intrusion check). Kamailio SIP edge, normalization, topology hiding and codec transcoding are still open.
- P5 slice one: `services/reports` on :50061 (gRPC `ListCdrs`/`Summarize`, `proto/reports/v1/reports.proto`) and :50062 (HTTP `GET /reports/cdrs`, `GET /reports/summary`) consumes `cdrs.normalized` (group `reports`) and rates each CDR via Catalogue `GetRate` with the OCS `ROUND(seconds*rate)` rule, writing `reports.cdrs` in ClickHouse (`ReplacingMergeTree(ingested_at)`, `ORDER BY (account_id, started_at, call_id)`, `FINAL` on reads; `rate_missing=true` when no rate exists, amount 0). Offsets commit only after a successful insert, so ingestion is at-least-once and dedup is the table engine. The HTTP facade validates `Authorization: Bearer` against identity `GET /me`, resolves accounts via `GET /accounts?tenant_id=`, forces resellers to their own tenant, lets admins pass `tenant_id` (400 without it), and returns 403 for role `user` (identity has no user↔account link). gRPC is internal/trusted. Envs: `REPORTS_CLICKHOUSE` (default `clickhouse://omnifoni:dev-only@clickhouse:9000`), `REPORTS_KAFKA`, `REPORTS_CATALOGUE_ADDR`, `REPORTS_IDENTITY_ADDR`, `REPORTS_ADDR`, `REPORTS_HTTP_ADDR`. Ingestion is forward-only; no backfill. `ops/bench-reports.sh` measures the 10M-row p95 target.
- P5 slice two: money reports mirror the money owners rather than re-aggregating. Payments gained gRPC `ListPayments` (keyset DESC on `(created_at, payment_id)`, cursor `base64url("<created_at_ms>|<payment_id>")`); Charging gained `ListCharges` (per-session aggregate of `ledger`, `amount_minor` is the negative sum of the ledger deltas, `balance_after` the newest row; window filters on the session's last charge; cursor `base64url("<last_charged_at_ms>|<session_id>")`) and `ListLowBalance` (ALL accounts, prepaid and postpaid, `balance <= threshold_minor`, order `balance ASC, account_id ASC`, cursor `base64url("<balance>|<account_id>")`). Reports re-exposes them as gRPC `ListPayments`/`ListCharges`/`ListLowBalance` and HTTP `GET /reports/payments`, `/reports/charges` (`from`+`to` required, same date semantics as CDR filters), `/reports/low-balance` (`threshold` in minor units, default 0; no date window). P5 slice three: `Summarize` gains `PREFIX` grouping with `prefix_len` (default 3, range 1–15) keyed on `left(destination, n)`; every report endpoint accepts `format=csv` (header uses the JSON field names, summary appends a `TOTAL` row, 10,000-data-row cap via internal 1000-row pages with no cursor). The facade applies the same tenant/account scoping as slice one; source non-`InvalidArgument` errors surface as HTTP 503. Limits default 100, max 1000. Envs: `REPORTS_PAYMENTS_ADDR` (payments:50060), `REPORTS_CHARGING_ADDR` (charging:50051).
- P5 slice four: switching serves `ListLiveCalls` (registry snapshot of in-flight calls: `max_seconds` from the OCS authorize, `charged_seconds` per tick, ended calls excluded, ordered `started_at ASC, call_id ASC`, empty `account_ids` = all). Reports re-exposes it as gRPC `ListLiveCalls` and HTTP `GET /reports/live-calls` (same tenant/auth scoping as the other reports; `format=csv` uses the shared helpers; empty scope returns an empty 200; source errors are 503). Env `REPORTS_SWITCHING_ADDR` (default switching:50052); the reports image now also copies switching/routing/sbc. Smoke seeds a `smoke`-tenant account + rate + LCR route and runs `cmd/smokelive` (start, list, stop).
- P5 slice five: `services/reports` also schedules recurring reports (Postgres `reports_sched` DB: `schedules`+`report_artifacts` tables; `sched_migrate.sql`). `REPORTS_SCHED_DSN` (default `postgres://postgres:dev-only@postgres:5432/reports_sched`; **empty disables the scheduler and its routes** with 503 `schedule_unavailable`) turns on a 1-minute ticker (`RunDueSchedules`, reconciliation `Sweep` pattern) that renders each due schedule (`daily|weekly|monthly` at `at_hour:at_minute` UTC; window `last_day|last_week|last_month|previous_month`) through the existing report API into a CSV artifact (10k-row cap, unique `(schedule_id, slot_key)` = at most one artifact per slot; missed runs are skipped, not backfilled) and publishes `scheduling.v1.ReportReadyEvent` to `report.ready` (`REPORTS_SCHED_TOPIC`; publish failures never roll back the artifact). Artifacts prune hourly past `REPORTS_SCHED_RETENTION_DAYS` (default 90). HTTP on :50062 with the same identity bearer + tenant scoping as the other reports: `POST/GET/PATCH/DELETE /scheduled-reports`, `GET /scheduled-reports/{id}/artifacts`, `GET /scheduled-reports/{id}/artifacts/{aid}/download`, `POST /scheduled-reports/{id}/run` (manual backfill, `manual-<uuid>` slot). Report kinds: `cdrs|summary|payments|charges|low_balance` (`summary` may group `prefix` with `prefix_len` 1-15). The reports image is unchanged (the proto generates into the reports module); compose adds `postgres` to `depends_on`. For an existing dev volume create the DB once: `docker exec omni-fon-postgres-1 createdb -U postgres reports_sched`.
- P5 slice six: `services/notifications` on :50064 consumes `report.ready` (group `notifications`), stores one deduped row per `artifact_id`+`recipient_email` in the `notifications` Postgres outbox, and sends plain-text email via `net/smtp` to Mailpit (`mailpit:1025`, UI http://localhost:8025). Kafka offsets commit only after the outbox insert; the worker claims due rows with `FOR UPDATE SKIP LOCKED`, retries SMTP failures up to `NOTIFICATIONS_MAX_ATTEMPTS` with exponential backoff, and marks terminal validation failures `failed`. Reports now stores the creator's identity email on schedules, publishes `recipient_email`/`artifact_url`/`expires_at_ms`, and accepts HMAC-SHA256 signed artifact download links (`REPORTS_ARTIFACT_SIGNING_SECRET`, `REPORTS_SIGNED_URL_TTL` ms, `REPORTS_PUBLIC_BASE_URL`). Invalid or expired links return 403. Envs: `NOTIFICATIONS_DSN`, `NOTIFICATIONS_KAFKA`, `NOTIFICATIONS_TOPIC_REPORT_READY`, `NOTIFICATIONS_GROUP`, `NOTIFICATIONS_SMTP_ADDR`, `NOTIFICATIONS_SMTP_FROM`, `NOTIFICATIONS_MAX_ATTEMPTS`, `NOTIFICATIONS_POLL_INTERVAL`, `NOTIFICATIONS_BATCH_SIZE`, `NOTIFICATIONS_ADDR`. `ops/smoke.sh` resets Mailpit, runs a scheduled report, waits for one email, and follows its signed link to CSV.
- P6 slice one: `services/fraud` on :50063 owns the toll-fraud MVP (gRPC `CheckCall`/`EndCall`/`ListAlerts`, `proto/fraud/v1/fraud.proto`, `fraud` DB). SBC consults Fraud after its own IP/barring playbook and before trunk reservation when `SBC_FRAUD_ADDR` is set; an outage denies `fraud_unavailable`, an empty `account_id` skips Fraud, and trunk denials release the Fraud reservation. Fraud uses deterministic prefix/CLI blocks and velocity caps for denials (`fraud_destination`, `fraud_cli`, `fraud_velocity_account`, `fraud_velocity_prefix`); the versioned `v1` advisory score never blocks, alerts at >= `FRAUD_ALERT_THRESHOLD` (default 60), writes `alerts`, and publishes `fraud.alerts`. It consumes `cdrs.normalized` (group `fraud`, manual commit after DB success) to convert reservations into completed usage and dedups by `call_id`. Switching passes `account_id` to SBC. Envs: `FRAUD_ADDR`, `FRAUD_DSN`, `FRAUD_KAFKA`, `FRAUD_TOPIC_ALERTS`, `FRAUD_ALERT_THRESHOLD`, `FRAUD_SOFT_ACCOUNT_CALLS`, `FRAUD_SOFT_PREFIX_CALLS`, `SBC_FRAUD_ADDR`. `cmd/fraudreplay` reads `services/fraud/testdata/fraud_cases.jsonl` and writes `docs/fraud-baseline.md`; the CI gate is precision >= 0.80 and recall >= 0.70. `ops/smoke.sh` seeds a velocity control and asserts denial plus an alert via `cmd/fraudsmoke`, printing `ok: fraud`.
- P6 slice two: the POPIA control pack lives in `docs/compliance/` (`README.md`, `data-classification.json`, `popia-control-matrix.md`, `runbooks/`). `tools/compliancecheck` is a standalone stdlib-only Go validator for the manifest's schema, retention rules, storage allowlist, evidence paths, and class/control coverage; run it with `make compliance`, which is also a prerequisite of `make test`. Retention entries without a runtime prune job are `documented_target`, not enforced; legal sign-off cells remain blank. No runtime deletion, KYC, lawful-intercept, residency, or operator UI was added.
- P6 slice three: `docs/security/gvisor-runtime-hardening.md` adds an opt-in `docker-compose.gvisor.yml` runtime override for the `payments` webhook processor (`make up-gvisor`, `make smoke-gvisor`, `make check-gvisor`); default compose/CI stay on runc, no rate-file parser or AI inference workload exists, and SIP/kamailio are not sandboxed. runsc installation and the positive-path gVisor smoke are manual gates on a runsc-enabled host.
- P4 remainder: `services/sipedge` fronts Kamailio (UDP 5060) with the existing switching policy/charging chain. Kamailio asks `POST /invite` (body `call_id|source_ip|from|to|ruri|h_entry|h_id`) before relaying to the LCR trunk `target_uri`; 200 returns the target, 403/503 map policy denials and outages to SIP replies. `POST /bye` stops the switching call on BYE/CANCEL. A 1 s reaper diffs switching `GET /live` against tracked dialogs and ends orphans via Kamailio `dlg.end_dlg` over `xhttp` JSON-RPC. Envs: `SWITCHING_HTTP_ADDR` (switching facade, `:50070`), `SIPEDGE_SHIM_ADDR` (`:50071`), `SIPEDGE_SWITCHING_HTTP` (`http://switching:50070`), `SIPEDGE_KAMAILIO_RPC` (`http://kamailio:5060/RPC`), `SIPEDGE_TRUNK_ACCOUNTS` (`ip=account,...`, unknown IP → 403 `ip_blocked`), `SIPEDGE_REAP_INTERVAL` (`1s`, `0` disables). Trunks without `target_uri` are excluded from LCR. No rtpengine/FreeSWITCH/registrations yet; `cmd/sipuas` + `cmd/sipsmoke` back `ok: sip` in `ops/smoke.sh`.
- Switching tests seed rates via Catalogue gRPC (CATALOGUE_ADDR, default localhost:50053) — the old direct-insert into `charging.rates` was a decoy from the stale volume and masked by cached test results until the routing wiring exposed it (`no_rate` denies).
- Switching imports charging's stubs via `replace omnifoni/charging => ../charging`, so its image builds with `context: ./services` and `dockerfile: switching/Dockerfile` (switching also `replace`s `omnifoni/sbc => ../sbc`, so its Dockerfile must `COPY sbc/` as well — a missing sibling COPY fails the build). Charging imports catalogue's stubs the same way.
- Switching tests seed the charging DB directly and gRPC to localhost:50051; charging tests seed rates via catalogue gRPC on localhost:50053; bufconn targets must use `passthrough:///bufnet`.
- Dev data layer: `make up` (docker compose: PostgreSQL 17, Valkey 8, Kafka 3.9.1 KRaft, ClickHouse 24.10, charging service on :50051). Smoke: `make smoke`. Tests: `make test` (needs the stack up, they hit real Postgres).
- Regenerate gRPC stubs with `make protoc` (needs protoc and protoc-gen-go/-go-grpc in /root/go/bin, PATH it).
- `charging.Migrate` is CREATE TABLE IF NOT EXISTS only; schema changes require dropping the charging tables (`docker exec omni-fon-postgres-1 psql -U postgres -d charging -c 'DROP TABLE IF EXISTS ledger, sessions, rates, accounts CASCADE'`) until real migrations exist.
- Money is integer minor units (1/10000 currency); rate per second is numeric(14,6) minor units; per-event cost is ROUND(delta*rate), half away from zero. Postpaid balances go negative down to -credit_limit.
- The rates table inside the charging DB is a ponytail placeholder until the Catalogue service exists.
- Postgres databases are created by `ops/postgres-init.sql` on first init only; recreating them requires deleting the `pgdata` volume.
- The `mediation` database (like all context DBs) is created by `ops/postgres-init.sql` on first init only; a fresh volume (`docker volume rm omni-fon_pgdata`) is required if the volume predates it.
- Host port 9000 is ClickHouse native, don't bind anything else to it. Health status must be read with `docker inspect --format '{{.State.Health.Status}}'`, `docker compose ps --status healthy` returns no rows on this CLI version.

- Observability (P0 debt): `services/observability` is a shared module (`omnifoni/observability`, imported via `replace omnifoni/observability => ../observability`). It installs OTLP/gRPC tracing (`OTEL_EXPORTER_OTLP_ENDPOINT`, default `jaeger:4317`, `off` disables; `OBS_SAMPLE_RATIO` default 1.0), a JSON slog handler carrying `service`/`trace_id`/`span_id`/`request_id`, and key-based redaction (`phone|msisdn|caller|callee|destination|email|token|password|authorization|secret`; values longer than 9 chars keep a 5-char prefix and last 4). Telemetry is fail-open: an exporter or Jaeger outage never fails a call or RPC. Jaeger all-in-one runs in compose (UI http://localhost:16686, OTLP 4317) and `make smoke` asserts spans for reconciliation, billing and payments. Any service whose Dockerfile copies `observability/` must build with `context: ./services`. Kafka traceparent is propagated by `InjectKafka`/`ExtractKafka` + `ConsumerSpan`; boot wiring is `SetupLogging`/`Init` plus `ServerOptions`/`ClientOptions`/`Middleware`. In-process span tests use `tracetest.SpanRecorder` (they export nothing), so Jaeger registration needs a live probe with `OTEL_EXPORTER_OTLP_ENDPOINT=127.0.0.1:4317` on the host.

## Hard constraints

- Clean-room: never read ASTPP source code, schemas, or licensed assets. Feature claims come only from the four ASTPP marketing pages cited in `docs/master-plan.md` sections 0 and 8.
- FOSS-only stack, licences verified per `docs/master-plan.md` section 4. No Terraform (BUSL), no Redis (licence), use Valkey.

## Environment

- Go lives in `/usr/local/go`, symlinked to `/usr/local/bin/go`. Installed outside apt; update by replacing the tarball.
- Docker daemon was started with `nohup dockerd` (no systemd); after host restart run `nohup dockerd >/var/log/dockerd.log 2>&1 &` before `make up`.
- `make up` reuses existing images and never rebuilds; after changing a service's code run `docker compose build <service>` before `make up` (or `docker compose up -d --build`). A stale image once masked both a broken Dockerfile and a code change.
- Host-side go tests reach the dev broker via 127.0.0.1 kafka in /etc/hosts (the broker advertises kafka:9092); keep the entry for host tests.
