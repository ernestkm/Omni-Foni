# Reports (P5 slice one) — design

Date: 2026-11-16
Status: approved design, pre-plan
Scope: P5 first slice — CDR ingestion into ClickHouse plus CDR-list and grouped-summary reports over gRPC and HTTP.

## 1. Goal

Start the P5 reporting phase with the analytics store and the two highest-value reports: a filterable CDR list and a grouped summary (calls, seconds, cost) by day, destination, account or trunk. Later P5 slices add the remaining section-1.1 reports (audit, product usage, email, payment, commission, low balance, activity, live switch monitoring, automated reports) on the same store and API shape.

## 2. Decisions taken in brainstorming

- **Scope**: ingestion + `ListCdrs` + `Summarize` only. The rest of the report suite is explicitly out of scope.
- **Shape**: one `services/reports` binary doing Kafka ingestion, ClickHouse writes and the query API — the payments precedent (HTTP + gRPC in one process), not a split ingester/query pair and not ClickHouse's Kafka engine.
- **Surface**: gRPC is the contract; a thin HTTP JSON facade serves UI/curl.
- **Money**: reports rates each CDR at ingestion through Catalogue, using the same `ROUND(seconds*rate)` rule as billing, and stores `rate_per_sec` + `amount_minor`. Billing remains the invoicing authority; reports is an independent consumer. Divergence is possible only when a catalogue rate changes between the two consumers processing the same CDR.
- **History**: forward-only ingestion. No backfill from billing; the smoke probe drives a real call to populate the store.
- **Tenancy**: the HTTP facade validates the session against identity `GET /me` and resolves accounts via identity `GET /accounts?tenant_id=`. Admins may target any tenant; resellers are forced to their own; role `user` is 403 because identity has no user↔account link yet. gRPC is internal/trusted, like billing and reconciliation.

## 3. Architecture

```
switching -> cdrs.raw -> mediation -> cdrs.normalized -> reports (group "reports")
                                                            |  GetRate -> catalogue :50053
                                                            v
                                                     ClickHouse reports.cdrs
                                                            ^
reports gRPC :50061 (ListCdrs, Summarize) <-----------------+
reports HTTP :50062 (bearer auth) -> identity :50056 (/me, /accounts) -> gRPC above
```

Reports owns the `reports` ClickHouse database and nothing else. It never reads billing, payments or identity databases directly.

## 4. Components

### 4.1 `services/reports` module

- Go module `omnifoni/reports` with `replace omnifoni/catalogue => ../catalogue` and `replace omnifoni/observability => ../observability`; stubs under `gen/reportspb` regenerated by `make protoc`.
- `main.go`: signal context, `observability.SetupLogging("reports")`/`Init`, ClickHouse connect + DDL, catalogue dial with `ClientOptions()`, Kafka consumer start, gRPC `:50061` with `ServerOptions()`, HTTP `:50062` with `observability.Middleware`.
- `ingest.go`: consumer loop (franz-go, group `reports`, manual commit). For each record: `observability.ExtractKafka`, `reports.ingest` span (`call_id`), unmarshal `mediation.v1.CallCdr`, validate, resolve rate, compute cost, batch-insert. Commit only after a successful insert; on error the batch is retried with backoff (at-least-once).
- `store.go`: ClickHouse DDL and queries (`InsertCdrs`, `ListCdrs`, `Summarize`).
- `money.go`: `RateCost(seconds int64, rate string) (int64, error)` using `math/big.Rat`, rounding half away from zero — the OCS rule, unit-tested against hand-computed values.
- `grpc.go`: `ReportsServer` implementing the proto.
- `http.go`: bearer auth, identity calls, query parsing, JSON encoding.
- `cmd/smokereports/main.go`: calls `Summarize` for the current month; used by `ops/smoke.sh`.

### 4.2 Validation and rating rules

- Invalid (`call_id` or `account_id` empty, `charged_seconds < 0`, `ended_at_ms < started_at_ms`) → log `cdr rejected` with a reason and skip the record (no dead-letter topic in this slice).
- Catalogue RPC error → return the error so the batch retries. An outage never silently zeroes money.
- `found=false` → insert with `rate_per_sec=0`, `amount_minor=0`, `rate_missing=true`. The CDR still appears in reports; the gap is visible per row.
- `found=true` → `amount_minor = RateCost(charged_seconds, rate_per_sec)`; store the rate string exactly as returned.
- Duplicate deliveries are absorbed by `ReplacingMergeTree`; queries use `FINAL`.

### 4.3 ClickHouse schema

```sql
CREATE DATABASE IF NOT EXISTS reports;

CREATE TABLE IF NOT EXISTS reports.cdrs (
  call_id         String,
  account_id      String,
  destination     String,
  cli             String,
  started_at      DateTime64(3, 'UTC'),
  ended_at        DateTime64(3, 'UTC'),
  charged_seconds Int64,
  end_reason      LowCardinality(String),
  trunk_id        LowCardinality(String),
  rate_per_sec    Decimal(14, 6),
  amount_minor    Int64,
  rate_missing    Bool,
  ingested_at     DateTime64(3, 'UTC') DEFAULT now64(3)
) ENGINE = ReplacingMergeTree(ingested_at)
PARTITION BY toYYYYMM(started_at)
ORDER BY (account_id, started_at, call_id);
```

The newest `ingested_at` wins for a `call_id`, so a replayed identical CDR is idempotent. `ListCdrs` orders by `(started_at DESC, call_id DESC)` and uses keyset pagination; both queries filter `account_id IN (...)` and `started_at` range so partition pruning keeps `FINAL` bounded. The 10M-row p95 target is validated by `make bench-reports`, not by `make test`.

### 4.4 Proto — `proto/reports/v1/reports.proto`

```proto
syntax = "proto3";
package reports.v1;
option go_package = "omnifoni/reports/gen/reportspb";

service Reports {
  rpc ListCdrs(ListCdrsRequest) returns (ListCdrsResponse);
  rpc Summarize(SummarizeRequest) returns (SummarizeResponse);
}

message CdrFilter {
  repeated string account_ids = 1;  // empty = no account restriction (internal callers only)
  string from = 2;                  // YYYY-MM-DD or RFC3339, required
  string to = 3;                    // YYYY-MM-DD (inclusive day) or RFC3339, required
  string destination_prefix = 4;
  string trunk_id = 5;
  string end_reason = 6;
}

message ListCdrsRequest { CdrFilter filter = 1; int32 limit = 2; string cursor = 3; }

message Cdr {
  string call_id = 1;
  string account_id = 2;
  string destination = 3;
  string cli = 4;
  int64 started_at_ms = 5;
  int64 ended_at_ms = 6;
  int64 charged_seconds = 7;
  string end_reason = 8;
  string trunk_id = 9;
  string rate_per_sec = 10;  // decimal string, as rated
  int64 amount_minor = 11;
  bool rate_missing = 12;
}

message ListCdrsResponse { repeated Cdr cdrs = 1; string next_cursor = 2; }

enum GroupBy {
  GROUP_BY_UNSPECIFIED = 0;
  DAY = 1;
  DESTINATION = 2;
  ACCOUNT = 3;
  TRUNK = 4;
}

message SummarizeRequest { CdrFilter filter = 1; GroupBy group_by = 2; }

message SummaryRow {
  string key = 1;          // YYYY-MM-DD, destination, account_id or trunk_id
  int64 calls = 2;
  int64 seconds = 3;
  int64 amount_minor = 4;
}

message SummarizeResponse { repeated SummaryRow rows = 1; SummaryRow totals = 2; }
```

Semantics:

- `limit` default 100, maximum 1000; values outside 1..1000 are clamped.
- Cursor is opaque base64url of `<started_at_ms>|<call_id>`; an unparsable cursor is `InvalidArgument`. The next page selects rows where `(started_at, call_id) < (cursor_ms, cursor_call_id)` under the `started_at DESC, call_id DESC` ordering.
- `from`/`to` are required; a missing or unparsable bound is `InvalidArgument`. `to=YYYY-MM-DD` means the whole UTC day.
- `Summarize` requires a non-`GROUP_BY_UNSPECIFIED` group; rows are ordered by `amount_minor DESC, key ASC`; `totals` is always present (zeros when no rows).
- `DAY` keys are UTC `YYYY-MM-DD`; `DESTINATION` keys are the full destination (country reporting is a later prefix-grouping slice); empty `trunk_id` groups under `""`.

### 4.5 HTTP facade

Routes (all require `Authorization: Bearer <session>`):

- `GET /reports/cdrs?from=&to=&account_id=&destination_prefix=&trunk_id=&end_reason=&limit=&cursor=`
- `GET /reports/summary?group_by=day|destination|account|trunk&from=&to=&account_id=&destination_prefix=&trunk_id=&end_reason=`

Auth flow per request:

1. `GET {REPORTS_IDENTITY_ADDR}/me` with the bearer token. Non-200 → 401.
2. Parse `role` and `tenant_id`. Role `user` → 403. Role `admin` uses the optional `tenant_id` query parameter and gets 400 when it is absent; reseller always uses their own `tenant_id`.
3. `GET {REPORTS_IDENTITY_ADDR}/accounts?tenant_id=<scope>` with the same token → `account_id` list. Identity error → 502.
4. Call the gRPC method with `account_ids` set to that list. An account filter supplied by the caller is intersected with the tenant's accounts; an empty intersection returns an empty result, never an error.

Response bodies mirror the proto: `{"cdrs":[...],"next_cursor":""}` and `{"rows":[...],"totals":{...}}`. Money stays integer minor units; `rate_per_sec` is a string. `account_id` may be repeated in the query string. JSON errors are `{"error":"..."}` with 400/401/403/502/503.

### 4.6 Errors

- ClickHouse unavailable at boot → exit non-zero (no query surface without a store). Runtime insert failures → retry with backoff, no commit. Query failures → `Unavailable`/503.
- Kafka unavailable → queries keep serving; ingestion retries until the broker returns.
- Catalogue unavailable → ingest retries; query surface unaffected.
- Telemetry stays fail-open.

### 4.7 Observability

- `reports.ingest` span per message (`call_id`), parented by the Kafka traceparent; `reports.list_cdrs` and `reports.summarize` spans (`group_by`, `from`, `to`, `rows`).
- Request-scoped logs use `slog.*Context`, so `trace_id`/`span_id`/`request_id` appear.
- `ops/smoke.sh` gains a `cmd/smokereports` probe (current month `Summarize`) and asserts `reports` in Jaeger's `/api/services`.

## 5. Testing

- Real ClickHouse from the dev compose for DDL, insert, dedup (`FINAL`), filters, grouping, totals and keyset pagination.
- Kafka-dependent ingest test skips when the broker is unavailable (repo convention); ClickHouse-dependent tests skip when it is unreachable.
- `RateCost` unit table: zero, sub-unit rounding, half-away-from-zero ties, large values.
- HTTP tests with an `httptest` identity server: 401 missing token, 403 role `user`, reseller tenant forced, admin tenant override, account intersection, identity 502.
- Live verification: drive one call through switching, then `ListCdrs`/`Summarize` show it and Jaeger shows `reports.ingest` in the same trace as `switching.start_call`.

## 6. Acceptance criteria

1. One call yields exactly one CDR row even when the message is delivered twice.
2. `amount_minor` equals billing's `invoice_lines.amount_minor` for every call rated by both (calls billing dead-letters as `no_rate` appear in reports with `rate_missing=true` and have no invoice line).
3. Summary totals equal the sum of the matching CDR rows for every group.
4. HTTP: 401 without a token, 403 for role `user`, and no cross-tenant account access.
5. `reports` appears in Jaeger and `make smoke` asserts it.
6. `make test` and `make smoke` pass.

## 7. Out of scope

- Audit log, product usage, email history, payment, commission, low-balance and activity reports.
- Live switch monitoring, realtime system monitoring logs, automated/scheduled reports.
- Country/prefix grouping, dashboards/UI, CSV/PDF export.
- Historical backfill from billing or Postgres.
- User↔account mapping (role `user` stays 403).
